1. **문의처가 없음.** 개인정보 처리방침 5항 "문의: 준비 중입니다", 이용약관 11항 "문의: 준비 중", 모든 쪽 하단 "문의: 준비 중". 개인정보 보호책임자는 "사이티드 대표"로만 적혀 있고 성명·연락처가 없음(개인정보 보호법 제30조 필수 기재사항). 감사 1의 P0-2가 **부분 해결**된 상태.

(감사 1의 P0-5 굵기 문제는 WebKit 굵기 탐침 비율 1.73으로 **해결 확인**, 실기기 확인은 함께 필요)

**최종 판정: 조건부 불합격(Conditional NO-GO).** 기능·성능·보안·접근성은 상용 수준입니다. 위 P0 2건(문의처 기재, iPhone 실기기 확인)만 해결되면 **공개 출시(GO)** 가능합니다. 둘 다 코드 작업이 거의 없는 운영 과제입니다. 10장의 체크리스트를 참고하세요.

### 2.2 도구별 관찰

**PDF 합치기** — 감사 1 지적이 거의 다 반영되었습니다. 비PDF 요약 알림, 비밀번호 칸 안 입력과 보기 토글, 결과 박스 순서, 저장될 이름 표시가 모두 좋습니다(`std/merge-m-06-done.png`). 남은 점: 비PDF 알림이 주 버튼 **아래**에 떠서 목록만 보는 사용자가 놓치기 쉽고, "notes.txt**은(는)**"처럼 기계식 조사가 보입니다.

**PDF 용량 줄이기** — 목표 용량 모드, 달성 실패 시 정직한 안내, 결과 박스 순서가 모범적입니다(`std/cmp-m-07-done-viewport.png`, `std/cmp-m-10-target-miss.png`).

**사진 용량 줄이기** — 휴대폰 크기 사진(3.6 MB, 4032×3024)을 200 KB 목표로 줄이면 3.4 s 만에 `3.6 MB → 192 KB · 94% 줄었습니다`, 원본/결과 비교 슬라이더가 나옵니다(`x/photo2-m390-done-fold.png`). 핵심 흐름은 훌륭합니다. 문제는 **작은 사진이 섞였을 때**입니다(`x/chrome-d1440-light-photo-3-done-fold.png`).
- 기본 목표는 500 KB입니다. 이미 281 KB, 340 KB인 사진에 "**더 줄일 수 없는 사진입니다. 원본을 그대로 쓰세요.**"라고 나오고 내려받기 버튼이 없습니다. 실제 이유는 "이미 목표보다 작다"인데, 사용자는 "도구가 실패했다"로 읽습니다.
- 26 KB 사진은 위치 정보를 지우느라 87 KB로 **커졌는데**(문구에는 "(늘어남)"이 있음), 상단 요약은 "3장 중 1장을 **줄였습니다**. 2장은 줄이지 못했습니다. 26 KB → 87 KB"입니다. 요약과 결과가 모순됩니다.
- 사진 목록에 **썸네일이 없고** 회색 아이콘만 보입니다(결과가 있는 사진만 썸네일이 생김). 사진 도구에서 "내가 고른 사진이 맞는지" 확인할 수 없습니다.
- 비이미지·0바이트·GIF를 목록에 오류 카드로 넣습니다(합치기와 불일치). 0바이트 파일은 "사진 파일이 아닙니다"라고 나오는데 "빈 파일입니다"가 정확합니다. 가짜 HEIC는 실행 전까지 오류가 표시되지 않습니다.
- "크기를 2025×1518**으로** 줄였습니다" — 숫자 뒤 조사 오류("1518**로**", 여덟 → 로).
- 단일 사진인데 요약이 "1장 중 1장을 줄였습니다."입니다. 한 장일 때는 "사진을 줄였습니다."가 자연스럽습니다.

**여권·증명사진 규격 맞추기** — 제출처 프리셋(출처·기준일 명시), 정수리·턱 안내선, "이 도구가 확인할 수 없는 조건", 외교부 검증 링크(외부 업로드 경고 포함), 확인란을 거쳐야 저장하는 흐름은 책임 한계 표현까지 훌륭합니다. 저해상도·파노라마는 저장을 막고 이유를 표시합니다.
- **완료 화면의 헤드라인과 내려받기가 고정 헤더 뒤로 들어갑니다.** 390·360·768·200% 모든 실행에서 포커스는 헤드라인에 갔지만 헤드라인·체크 칩이 헤더 뒤에 숨고 내려받기 버튼은 위쪽이 잘립니다(`x/chrome-m390-light-idp-3-done-fold.png`, `x/msedge-m390-dark-idp-3-done-fold.png`). `scroll-margin-top` 누락으로 보입니다. 표준 스크립트 검사는 버튼 **아래쪽**만 봐서 통과했습니다.
- 확인 목록이 모바일에서 매우 길어 "규격에 맞춰 저장" 버튼이 사진 아래 약 2화면 뒤에 있습니다(`std/idp-m-02-adjust.png`).
- 얼굴이 없거나 두 명인 사진도 경고 없이 조정 화면으로 갑니다. 수동 맞춤 방식이라 허용되지만 "얼굴을 찾지 못했습니다. 안내선에 직접 맞춰 주세요" 같은 한 줄이 있으면 좋습니다.
- GIF 오류가 "움직이는 이미지는 아직 **줄일 수** 없습니다"로 나옵니다. 사진 줄이기 도구 문구를 그대로 쓴 것이라 이 도구에는 맞지 않습니다("쓸 수 없습니다").
- 완료 헤드라인 "413×531 px · 71 KB · **300 dpi**" — dpi는 일반인이 모르는 말입니다.
- H1 "여권사진 규격 맞추기"와 메뉴·카드·JSON-LD 이름 "여권·증명사진 규격 맞추기"가 다릅니다.

**HWP→PDF 변환** — 오류 문구가 모두 명확하고 포커스가 오류로 이동합니다(암호, 배포용, 손상, 이름만 바꾼 문서, 휴대폰 26 MB 제한). 인쇄 창 방식의 PDF 저장을 브라우저별로 안내하는 설계도 좋습니다.
- **평범한 법령 서식(`law09.hwp`, 20쪽, 수식 1개)이 "수식·도형이 많아 변환 결과가 원본과 다를 수 있습니다"로 분류되어 주 버튼이 사라지고 흐린 "그래도 PDF로 저장"만 남습니다**(`x/chrome-m390-light-hwp-2-ready-fold.png`). 미리보기는 원본과 다를 바 없어 보입니다. 공문서에는 표·도형이 흔하므로 이 판정이 자주 걸리면 사용자는 "실패"로 느낍니다. 기준을 완화하거나, 미리보기를 확인한 뒤에는 "PDF로 저장"을 주 버튼으로 올리세요.
- 파일을 연 뒤 포커스가 파일명 헤딩(`law05.hwp · 1쪽`)으로 가면서 굵은 청록 사각 테두리가 생겨 **입력칸처럼 보입니다**(모든 브라우저). 프로그램 포커스에는 `:focus-visible` 링을 억제하거나 헤딩 스타일에 맞는 밑줄형 표시를 쓰세요.
- 법적 고지 두 문장이 도움말 안과 푸터 위에 **두 번** 나옵니다.
- "관련 도구"가 2개뿐입니다(다른 도구는 4개).

- 두 번째 사용부터는 서비스 워커 캐시 덕분에 엔진 대기가 사라지고, 오프라인에서도 동작합니다(6.3절).

### 4.3 상태 전환 중 레이아웃 이동(CLS)
정적 페이지 CLS는 0–0.002입니다. 그러나 도구 상태 전환에서 누적 이동이 큽니다: 모바일 합치기 오프라인 0.191, 줄이기 목표 미달 0.181, 합치기 청크 오류 0.150, 줄이기 완료 0.148(`std/static.json`). 결과 박스·오류 패널이 사용자 입력 후 500 ms 이상 지나 콘텐츠 위에 끼어들어 아래를 밀기 때문입니다. 크롬 사용자 경험 보고서(CrUX)의 CLS는 페이지 수명 전체를 세므로, 광고를 붙이면 합산되어 0.1을 넘을 수 있습니다(P2-6).

### 6.2 서비스 워커와 오프라인
- 등록: 첫 방문 idle 뒤 등록, 프리캐시 26개(셸 HTML 8쪽 + 공용 자산), 엔진(`/vendor/`, `/fonts/`)은 쓸 때 캐시(cache-first). 내비게이션은 network-first(3 s 제한) → 캐시 → `/offline/`.
- 실측(`sw.cjs`, 390 px): 온라인에서 합치기와 사진 줄이기를 한 번씩 쓴 뒤 **비행기 모드**로 바꾸면

  - `/photo-compress/` 다시 열기와 줄이기 완료 ✅
  - `/pdf-compress/` 열기와 파일 확인 ✅(pdf.js가 합치기에서 이미 캐시됨)
  - `/hwp-to-pdf/` 열기 ✅, 한 번도 안 쓴 HWP 엔진은 "인터넷 연결이 끊겨 처리 도구를 불러오지 못했습니다. 파일에는 문제가 없습니다" ✅(`x/offline_hwp-to-pdf_.png`)
  - 캐시에 없는 `/licenses/` → `/offline/` 페이지 ✅("한 번 사용한 도구는 인터넷 없이도 열립니다" + 도구 링크)
- 업데이트: `skipWaiting` 자동 실행 없이 "새 버전이 있습니다. [새로고침]" 바를 도구 작업 중이 아닐 때만 보여 줌 ✅. 이전 캐시는 한 세대만 남기고 정리.
- 홈 약속 "한 번 사용한 도구는 인터넷을 끊어도 동작합니다. 비행기 모드에서 직접 확인해 보세요."는 **사실로 확인**되었습니다. 경쟁 서비스가 흉내 낼 수 없는 신뢰 장치입니다.
- 개선: "한 번 사용한 도구"는 사용자가 기억하기 어렵습니다. 도구 첫 사용 후 "이제 이 도구는 인터넷 없이도 쓸 수 있습니다" 한 줄을 결과 박스에 보여 주면 약속이 체감됩니다.

### 7.2 오너 관점: "업로드"라는 말을 모르는 사용자
페이지 문구 전체(`text.txt`, `faq.txt`)에서 **업로드 9회, 서버 13회, 브라우저 26회, 네트워크 6회, 메모리 11회, EXIF 3회, px 14회, ppi 7회, dpi 1회**가 나옵니다. 문제는 횟수보다 위치입니다. 이 단어들이 **"안전하다"는 핵심 약속**을 전달하는 자리(배지, H1, 리드, 드롭존, 안전한 이유)에 있습니다. 약속을 이해하지 못하면 차별점이 사라집니다.
