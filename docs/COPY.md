# 문서딱 한국어 문구 가이드

서비스 이름은 **문서딱**입니다(2026-09-30 변경, 오너). 이름은 언제나 "문서딱"으로 쓰고, "docttak"은 주소(docttak.com)로만 씁니다("Docttak", "독딱" 금지, 빌드 테스트가 막음). 공유 미리보기 문구는 `src/data/og.json`에 있습니다(설명 80자 이하). 태그라인: "내야 하는 문서·사진, 용량과 규격에 딱 맞춰 드려요". 코드에서는 `SITE.name`, `SITE.tagline`만 씁니다.

## 문체
- 본문은 합니다체로 씁니다. ("처리합니다", "저장되지 않습니다")
- 예외(오너, Polish Q): 태그라인, 홈 첫 화면(배지·H1·리드), 개인정보 처리방침, 사진 결과의 "원본 그대로 받으셔도 돼요"는 문서딱 말투(해요체)로 씁니다.
- 예외(Sprint C, C2): /remove-background/의 도구 안 문구(맞는 사진·한계 안내, 받기 동의, 진행·오류 상태, 결과)는 브리프 문구를 그대로 따라 해요체로 씁니다. 사용 방법·안전한 이유·FAQ는 합니다체입니다.
- 예외(Arch, G2 A0): /hwp-viewer/의 "원본과 다르게 보일 수 있어요."와 찾기 상태 "찾기를 멈췄어요"는 브리프 문구 그대로(해요체) 둡니다. 나머지 도구 문구는 합니다체입니다.
- 느낌표를 쓰지 않습니다. 과장("최고", "완벽", "100 % 안전")을 쓰지 않습니다.
- 전문 용어 대신 쉬운 말을 씁니다. "드롭존" → "여기에 파일을 끌어다 놓으세요".
- 전문 용어는 쉬운 말 뒤 괄호 안에 씁니다: "제출용 선명도 (약 150 ppi)". 선명도 단위는 "ppi"만 씁니다. "dpi"는 어디에도 쓰지 않고 "해상도 300"처럼 씁니다.
- 허용 용어(사진): "KB", "MB", "WebP", "ZIP". 픽셀 수는 "413×531픽셀"로 쓰고, 사용자가 숫자를 읽거나 입력해야 하는 쪽에서만 한 번 "픽셀(px)"로 풀어 줍니다(쪽마다 최대 1회). "화소"나 "MP"는 항상 숫자와 함께 씁니다: "6,400만 화소(64 MP)".

## 쉬운 말 (Polish Q, 오너)
일반 사용자는 업로드·서버·브라우저·네트워크·메모리·EXIF·px·dpi를 모릅니다. 화면에 보이는 문구(제목, 설명, 본문, 오류, 법적 고지)에는 쓰지 않고, 빌드 테스트(`tests/unit/postbuild.test.ts` "plain language")가 막습니다. 예외는 /licenses/(소프트웨어 이름)뿐입니다.

| 쓰지 않는 말 | 대신 쓰는 말 |
|---|---|
| 업로드 없음, 업로드하지 않습니다 | 밖으로 보내지 않습니다, 파일이 밖으로 안 나가요 |
| 서버로 전송되지 않습니다 | 이 기기 밖으로 나가지 않습니다, 어디로도 보내지 않습니다 |
| 서버 (다른 사이트 설명) | 그 회사 컴퓨터 |
| 브라우저 | 이 화면, 이 페이지, 지금 쓰는 앱 |
| 네트워크로 전송 | 인터넷으로 보내기 |
| 메모리가 부족해 | 이 기기에서 처리하기에 너무 커서, 한 번에 처리할 수 있는 양 |
| 사진 정보(EXIF) | 촬영 위치, 찍은 기기와 날짜 같은 사진 정보 |
| px | 픽셀 |
| dpi | 해상도 |
| 개발자 도구 네트워크 탭 | 비행기 모드로 직접 확인 |

- 조사는 `src/lib/ui/josa.ts`의 `josa()`로 고릅니다. 변수(파일 이름, 숫자, 서비스 이름) 뒤에 조사를 직접 쓰거나 "은(는)"처럼 쓰지 않습니다. 숫자는 읽는 소리대로 고릅니다(2025×1518**로**).
- 사진은 "장"으로 셉니다: `12장`.
- 확인할 수 있는 사실만 말합니다. 보안 문구는 e2e 테스트가 증명하는 범위("파일은 이 기기 밖으로 전송되지 않습니다")까지만 씁니다.

- 보조용언은 띄어 씁니다: "받아 주세요", "골라 주세요", "마무리하는 중".

### 배경 지우기 예외 (C2-cloud, 오너 승인 2026-10-02)
`PUBLIC_BG_CLOUD=1` 빌드에서만 나오는 문장입니다. 사진을 보내는 도구는 배경 지우기뿐이므로, 예외 문장은 홈·개인정보 처리방침·이용약관·/remove-background/ 네 페이지에만 씁니다(check-dist가 막습니다). 다른 도구와 안내 페이지의 "어디로도 보내지 않아요"는 그대로 참입니다.

- 홈 첫 화면 각주: `* 배경 지우기만 예외예요. 사진을 잠깐 보내 처리하고 바로 지워요. 원하면 보내지 않고 처리할 수도 있어요.`
- 홈 안전 항목: `파일은 인터넷으로 어디에도 보내지지 않습니다. (배경 지우기는 예외, 아래 설명)`
- 개인정보 처리방침 2항 제목: `파일은 어디로도 보내지 않아요 (배경 지우기만 예외: 3항)`, 3항 `배경 지우기에서 사진을 보내는 경우`(목적, 항목, 처리와 보관, 처리 위탁, 국외 이전), 개인정보 보호책임자
- 이용약관 설명: `파일을 기기 안에서 처리하는 (배경 지우기 제외)`
- 도구 안내(사진 고르기 위, 늘 보임): `배경 지우기를 누르면 사진을 작게 줄인 사본 1장을 Cloudflare(미국 회사)로 보내 배경을 지우고, 결과를 받으면 바로 지워요. 문서딱은 사진을 저장하지 않아요.` / `보내고 싶지 않으면 사진을 보내지 않고 기기에서 처리를 고르세요 (처음 한 번 약 N MB).`
- 버튼: `배경 지우기`(보내기, 누르는 것이 동의), `사진을 보내지 않고 기기에서 처리 (처음 한 번 약 N MB 받기)`. N은 실제 받는 크기(`aboutMB`)입니다.
- "Cloudflare 즉시 삭제"라고 쓰지 않습니다. Cloudflare의 처리 기록 보관은 Cloudflare 개인정보처리방침을 따른다고만 씁니다.

## 버튼
- 짧게 쓰고, 누르면 무슨 일이 일어나는지 이름으로 말합니다: "PDF 파일 선택", "파일 추가", "PDF 3개 합치기", "내려받기", "다른 파일 처리하기", "취소". ("처음부터"처럼 결과를 알 수 없는 이름은 쓰지 않습니다.)
- 목록 항목 버튼의 aria-label에는 파일 이름을 넣습니다: "{파일명} 위로 이동".

- 여권·증명사진: 머리 윗부분은 "정수리(머리카락 제외)"로 씁니다. 머리 길이 값에는 "추정"을 붙이고, 도구의 기본 위치는 "규격"이라 부르지 않습니다(규격은 기관이 정한 값만). 사진 수는 "장"으로 셉니다.

## 오류 문구
- 두 문장으로 씁니다. 첫 문장은 무슨 일이 있었는지, 둘째 문장은 무엇을 하면 되는지.
- 사용자를 탓하지 않습니다. ("잘못된 파일입니다" 대신 "파일이 손상되었거나 다운로드가 완료되지 않았습니다. 원본을 다시 받아 주세요.")
- 처리 도구(엔진)를 불러오지 못한 것은 파일 탓이 아닙니다. 파일 오류 문구를 쓰지 않고 "처리 도구를 불러오지 못했습니다. 파일에는 문제가 없습니다. …새로고침해 주세요."로 안내합니다.
- 관련된 파일이 있으면 파일 이름을 앞에 붙입니다: "{파일명}: …".
- 제한 안내에는 숫자와 이유를 함께 씁니다: "파일 합계가 150 MB를 넘으면 휴대폰의 메모리로는 합칠 수 없어 …".

## 숫자와 단위
- 숫자와 단위 사이는 띄웁니다: `12.4 MB`, `3 KB`. 단, 쪽수와 퍼센트는 붙입니다: `3쪽`, `1,500쪽`, `88% 줄었습니다`.
- 파일 크기는 1 MB(1,048,576바이트) 미만이면 KB로 씁니다: `0.1 KB`, `9.8 KB`, `94 KB`, `1,023 KB`. 1 MB부터 `12.4 MB`.
- PDF 페이지는 "쪽"으로 셉니다. 파일 개수는 "개", 건수는 "건"입니다.
- 천 단위 쉼표를 씁니다: `1,500쪽`.

## 도구 페이지 구성
- H1에는 검색 키워드를 그대로 넣습니다. (예: "PDF 합치기")
- 파일 선택 버튼 옆에 "파일은 이 기기 밖으로 전송되지 않습니다."와 개인정보 처리방침 링크를 둡니다.
- H1은 메뉴·카드·JSON-LD의 도구 이름과 같습니다(`tools.ts`의 `name` = `h1`, 단위 테스트가 확인).
- 사용 방법은 3단계, "안전한 이유" 블록 1개, 자주 묻는 질문은 실제 검색 의도에 답하는 4–6개입니다.
- 제목 형식: `{도구명} — 파일을 보내지 않고 무료로 | 문서딱`(`TITLE_SUFFIX`). 설명은 80–120자이고 키워드와 "파일을 밖으로 보내지 않음" 이점을 쉬운 말로 담습니다.

## 사이트 설명 (홈 메타·OG·JSON-LD)
- 공개된 도구만 말합니다. 문장은 `src/data/site.ts`가 `tools.ts`에서 만듭니다.
- 형식: "{공개 도구 이름을 ·로 이음}. 파일은 내 폰·컴퓨터 밖으로 나가지 않아요. 가입 없이 무료."
- 변수 뒤에 조사를 붙이지 않습니다(도구 이름이 바뀌어도 문장이 맞도록). 길이는 80–120자이고 테스트가 확인합니다.
- 홈 공유 미리보기(og:description)는 도구 이름을 나열하지 않습니다(Sprint C: 도구 7개의 이름만으로 80자를 넘음). 준비 중인 도구 이름도 쓰지 않습니다.
- 준비 중인 도구는 홈의 "준비 중" 목록에 이름만 씁니다. 링크, 날짜, "곧 공개"를 쓰지 않습니다.

## 출시 체크리스트
- 도구를 공개하거나 내릴 때는 tools.ts status만 바꾼다. 홈·메타·OG·JSON-LD·404·메뉴가 따라 바뀌고 테스트가 확인한다.
- 도구 페이지를 실제로 바꾸면 tools.ts의 `updated`(YYYY-MM-DD)를, 약관·개인정보·라이선스 페이지를 바꾸면 legal.ts의 `LEGAL_UPDATED`를 올린다. sitemap의 lastmod가 된다.

## 안내 페이지 (Growth G)
- 안내(/guide/)는 해요체로 쓴다. 느낌표, 과장 없음. 쉬운 말 규칙은 같다(테스트가 막음).
- 규격 숫자는 인용한 공식 안내, 프리셋, 도구 사실에서만 가져온다. 운영 방법은 docs/GROWTH-RUNBOOK.md.
- 안내 본문·FAQ·출처는 시스템 글꼴로 보인다(UI 글꼴 예산). UI 글꼴에는 안내의 제목·답·버튼 글자만 들어간다.
