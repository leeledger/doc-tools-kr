# 안올림 한국어 문구 가이드

## 문체
- 본문은 합니다체로 씁니다. ("처리합니다", "저장되지 않습니다")
- 느낌표를 쓰지 않습니다. 과장("최고", "완벽", "100 % 안전")을 쓰지 않습니다.
- 전문 용어 대신 쉬운 말을 씁니다. "드롭존" → "여기에 파일을 끌어다 놓으세요".
- 전문 용어는 쉬운 말 뒤 괄호 안에 씁니다: "제출용 선명도 (약 150 ppi)". 선명도 단위는 "ppi"만 씁니다("dpi"는 쓰지 않습니다).
- 허용 용어(사진): "KB", "MB", "px", "WebP", "ZIP", "EXIF". EXIF는 처음 쓸 때 "사진 정보(EXIF)"로 씁니다. "화소"나 "MP"는 항상 숫자와 함께 씁니다: "6,400만 화소(64 MP)".
- 사진은 "장"으로 셉니다: `12장`.
- 확인할 수 있는 사실만 말합니다. 보안 문구는 e2e 테스트가 증명하는 범위("파일은 이 기기 밖으로 전송되지 않습니다")까지만 씁니다.

- 보조용언은 띄어 씁니다: "받아 주세요", "골라 주세요", "마무리하는 중".

## 버튼
- 짧게 쓰고, 누르면 무슨 일이 일어나는지 이름으로 말합니다: "PDF 파일 선택", "파일 추가", "PDF 3개 합치기", "내려받기", "다른 파일 처리하기", "취소". ("처음부터"처럼 결과를 알 수 없는 이름은 쓰지 않습니다.)
- 목록 항목 버튼의 aria-label에는 파일 이름을 넣습니다: "{파일명} 위로 이동".

## 오류 문구
- 두 문장으로 씁니다. 첫 문장은 무슨 일이 있었는지, 둘째 문장은 무엇을 하면 되는지.
- 사용자를 탓하지 않습니다. ("잘못된 파일입니다" 대신 "파일이 손상되었거나 다운로드가 완료되지 않았습니다. 원본을 다시 받아 주세요.")
- 처리 도구(엔진)를 불러오지 못한 것은 파일 탓이 아닙니다. 파일 오류 문구를 쓰지 않고 "처리 도구를 불러오지 못했습니다. 파일에는 문제가 없습니다. …새로고침해 주세요."로 안내합니다.
- 관련된 파일이 있으면 파일 이름을 앞에 붙입니다: "{파일명}: …".
- 제한 안내에는 숫자와 이유를 함께 씁니다: "파일 합계가 150 MB를 넘으면 휴대폰의 메모리로는 합칠 수 없어 …".

## 숫자와 단위
- 숫자와 단위 사이는 띄웁니다: `12.4 MB`, `3 KB`. 단, 쪽수와 퍼센트는 붙입니다: `3쪽`, `1,500쪽`, `88% 줄었습니다`.
- 파일 크기는 1 MB(1,048,576바이트) 미만이면 KB로 씁니다: `0.1 KB`, `9.8 KB`, `94 KB`, `1,023 KB`. 1 MB부터 `12.4 MB`.
- PDF 페이지는 "쪽"으로 셉니다. 파일 개수는 "개", 건수는 "건"입니다.
- 천 단위 쉼표를 씁니다: `1,500쪽`.

## 도구 페이지 구성
- H1에는 검색 키워드를 그대로 넣습니다. (예: "PDF 합치기")
- 파일 선택 버튼 옆에 "파일은 이 기기 밖으로 전송되지 않습니다."와 개인정보 처리방침 링크를 둡니다.
- 사용 방법은 3단계, "안전한 이유" 블록 1개, 자주 묻는 질문은 실제 검색 의도에 답하는 4–6개입니다.
- 제목 형식: `{도구명} — 업로드 없이 브라우저에서 무료로 | 안올림`. 설명은 80–120자이고 키워드와 업로드 없음 이점을 담습니다.

## 사이트 설명 (홈 메타·OG·JSON-LD)
- 공개된 도구만 말합니다. 문장은 `src/data/site.ts`가 `tools.ts`에서 만듭니다.
- 형식: "{공개 도구 이름을 ·로 이음}. 파일 업로드 없이 내 브라우저 안에서 바로 처리하고, 파일은 서버로 전송되지 않습니다. 회원가입 없이 무료."
- 변수 뒤에 조사를 붙이지 않습니다(도구 이름이 바뀌어도 문장이 맞도록). 길이는 80–120자이고 테스트가 확인합니다.
- 준비 중인 도구는 홈의 "준비 중" 목록에 이름만 씁니다. 링크, 날짜, "곧 공개"를 쓰지 않습니다.

## 출시 체크리스트
- 도구를 공개하거나 내릴 때는 tools.ts status만 바꾼다. 홈·메타·OG·JSON-LD·404·메뉴가 따라 바뀌고 테스트가 확인한다.
