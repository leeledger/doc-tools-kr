# 문서딱 수익 모델 · 운영 자동화 플랜 (2026-10-01)

원칙은 네 가지다.
- 도구는 영구 무료다.
- 수익은 트래픽에서 나온다.
- 파일은 어떤 경우에도 기기 밖으로 나가지 않는다.
- 운영은 사람 손 없이 돌아가야 한다. 사람이 꼭 해야 하는 일은 §5에만 적는다.

## 1. 수익원과 도입 조건

### 수익화 시점 검증 (2026-10-10, 실측 4일)
- **실측:** 10/7~10/10 방문 267, 페이지뷰 372. 미국 146은 대부분 배포 후 자동 점검으로 보이며(2026-10-10부터 통계에서 제외), 실제 한국 방문은 하루 25~35회 → 월 약 1,000방문·1,400 PV. 유입: 직접 190, 네이버 블로그 51, 네이버 검색 22, 구글 4.
- **필요량:** 월 10만 원 = 월 2.5만~5만 PV, 월 30만 원 = 월 7.5만~15만 PV (RPM 2,000~4,000원 가정). 현재의 20~100배.
- **시나리오(월 1,400 PV 출발):** 낙관(월 +60%) 월 10만 원 2027년 4~5월 · 기본(월 +40%) 2027년 6~9월, 월 30만 원 2027년 10월~2028년 초 · 보수(월 +20%) 2028년 이후.
- **판단 시점:** 2026-11-10에 4주 실측으로 성장률을 다시 계산한다(자동 점검 제외 데이터). 하루 실제 방문 100회 미만이면 콘텐츠·유입 전략을 먼저 재검토한다.
- **단계 (기본 시나리오 기준, 조건 충족이 우선):** 실제 방문 하루 100회(R1)는 2027년 2월 전후 → 애드센스 신청 · 월 5만 PV(R2 조건)는 2027년 8월 전후 → 증명사진 결과 화면 맥락형 제휴 · 월 10만 PV 이상에서 사진관·인화 업체 직접 광고 검토. 낙관 시나리오면 각각 2~3개월 앞당겨진다.

## 3. 자동화 설계 (GitHub Actions 중심, 실행 중 AI 토큰 0)
모든 작업은 결과를 GitHub 이슈나 PR로 남긴다. 사람이 판단할 일만 이슈로 올리고, 나머지는 자동으로 끝낸다.

| ID | 언제 | 무엇을 | 필요한 비밀값 |
|---|---|---|---|
| A-1 배포 후 점검 | main 푸시 → Cloudflare 배포 완료(라이브 `build-id`가 커밋과 같아질 때까지 대기) | ① `smoke:assets` ② 라이브 스모크(도구 5개 실제 처리, 외부 요청 0, 콘솔 오류 0) ③ 실패 시 이슈를 연다 | 없음 |
| A-2 색인 알림 | A-1 통과 직후 | 바뀐 URL을 sitemap lastmod 차이로 골라 IndexNow(Bing·네이버)에 핑한다 | 없음(키 파일은 공개) |
| A-3 출처 감시 | 주 1회 | 안내 페이지가 인용한 공식 출처 URL을 가져와 인용 문구가 그대로 있는지 확인한다. 바뀌면 "규격 변경 의심" 이슈를 연다(페이지, 출처, 이전/현재 문구). | 없음 |
| A-4 사이트 건강 | 매일 | 모든 sitemap URL이 200인지, OG·JSON-LD·canonical, 외부 스크립트 0개(Cloudflare 삽입 감지 포함), 내부 링크 깨짐, 응답 시간을 본다. 실패 시 이슈를 연다. | 없음 |
| A-5 성장 리포트 | 주 1회(월요일) | 서치콘솔 API로 노출·클릭·순위 상위 쿼리, Cloudflare GraphQL로 요청·대역폭을 가져와 `reports/growth/YYYY-WW.md`에 커밋하고 요약 이슈를 연다. 목표·중단 기준과 비교한다. | `GSC_SERVICE_ACCOUNT_JSON`, `CF_API_TOKEN`(Analytics Read) |
| A-6 기회 발굴 | 주 1회(A-5 뒤) | 노출은 많고 클릭이 적은 쿼리, 아직 안내 페이지가 없는 쿼리를 골라 "새 안내 페이지 후보" 이슈를 만든다(쿼리, 노출, 추천 도구 딥링크). | A-5와 같음 |
| A-7 콘텐츠 제작 루프 | 주 1회(클라우드 Claude 루틴) | A-6 이슈 상위 1~2개를 Arch→Bob→Richard 절차로 브랜치에서 만든다(공식 출처를 직접 가져온 것만). CI가 녹색이고 Richard가 "clear"면 PR을 자동 병합한다. 그 뒤 A-1·A-2가 이어진다. | Claude 루틴(구독 사용량) |
| M-3 수익화 트리거 | 주 1회 | §1의 R1 조건을 확인한다. 충족되면 "애드센스 신청 준비 완료" 이슈를 연다(체크리스트 포함). | A-5와 같음 |
| M-4 수익 리포트 | 승인 후 주 1회 | AdSense Management API로 수익·RPM·페이지별 실적을 가져와 성장 리포트에 합친다. | `ADSENSE_OAUTH`(승인 후) |

**안전장치**
- 자동 병합은 CI 전체 녹색(e2e 5개 브라우저·no-upload·라이선스·예산)과 리뷰 clear가 함께 있어야만 한다.
- main 보호 규칙: PR + CI 필수, 직접 푸시 금지(배포 게이트용 예외는 관리자만).
- 자동화는 사이트에 추적 코드나 외부 스크립트를 넣지 않는다. 데이터는 서버 쪽 API로만 가져온다.

## 4. 단계별 일정
1. **지금~2주:** A-1~A-4, A-5·A-6 구현. 사람은 비밀값만 넣는다. main 보호 규칙을 켠다.
2. **2~4주:** A-7 루틴을 켜고 안내 페이지를 주 1~2개 늘린다. 광고 설계(M1)를 플래그 꺼진 상태로 만들어 둔다.
   - 들어갈 것: 개인정보처리방침 v2, 동의 처리, ads.txt, CSP에 광고 출처만 허용, 도구 처리 영역 격리
3. **1~3개월:** M-3이 조건 충족을 알리면 애드센스를 신청한다. 신청 버튼은 사람이 누르고 나머지는 자동이다.
4. **승인 후:** 플래그로 광고를 켜고 M-4로 실측 RPM을 확인한다. 이 실측값으로 §1 목표를 갱신한다.
