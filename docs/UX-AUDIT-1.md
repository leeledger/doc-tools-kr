### P0 — 상용이라 부르기 전 반드시 고칠 것 (요약)
1. **엔진 로드 실패를 "파일이 손상되었습니다"로 잘못 안내함.** 오프라인이거나 배포 직후에 탭을 계속 열어 둔 경우 모든 파일이 "손상"으로 표시됨 (두 도구 모두)
2. **개인정보 처리방침에 "문의처는 곧 안내합니다"가 그대로 있음.** 운영자, 개인정보 보호책임자, 연락처가 없음
3. **모바일 PDF 용량 줄이기 결과 화면에서 내려받기 버튼이 화면 밖에 있음.** 미리보기 두 장이 위를 차지하고, 포커스도 화면 밖 버튼으로 이동함
4. **홈과 메타 설명이 아직 없는 기능을 약속함.** HWP 변환, 여권사진, 사진 줄이기를 광고해서 검색으로 들어온 사용자가 이탈함
5. **iOS Safari 실기기에서 글꼴 굵기를 확인해야 함.** Playwright WebKit에서는 모든 굵기가 Regular로 렌더링되어 위계가 사라짐. Windows WebKit 포트의 한계일 가능성이 높지만 실기기 확인 전에는 출시하지 말 것

### 3.3 기능과 약속의 차이
- 홈 카드는 "**제출 용량 제한에 맞게** PDF를 줄입니다"라고 하지만 도구에는 목표 용량(예: 5 MB·10 MB·20 MB 이하) 입력도, "N MB 제한 통과" 표시도 없습니다. 한국 사용자의 실제 과업은 "정부24·채용 사이트 10 MB 제한 통과"입니다.
- 모바일에서 "또는 여기에 파일을 끌어다 놓으세요"가 그대로 보입니다(터치 기기에서는 끌어다 놓을 수 없음). `fold-m360-compress.png`
- Slow 4G와 CPU 4배 저하 환경에서 파일을 고른 뒤 버튼이 켜지기까지 **합치기 8.5초, 줄이기 6.7초**가 걸리고, 그동안 "확인 중" 썸네일만 보입니다(`slow4g-merge-loading.png`). 처음 쓸 때 엔진(약 0.4–0.8 MB br)을 받는 시간인데, 사용자는 이유를 모릅니다. 줄이기 실행은 11.2초가 걸렸습니다.

### 3.4 권고 (도구 UX)
- **엔진 로드 실패 전용 오류**: `import()`나 `fetch(wasm)` 실패를 파일 파싱 오류와 분리하세요. 문구 예: "처리 도구를 불러오지 못했습니다. 인터넷 연결을 확인하거나 새로고침해 주세요. 파일에는 문제가 없습니다." + [새로고침] 버튼. 오프라인이면 `navigator.onLine`으로 구분합니다.
- **엔진 미리 받기**: 페이지가 idle일 때, 또는 선택 버튼의 `pointerdown`/드롭존의 `dragenter` 순간에 엔진 청크와 워커를 미리 받으세요(`<link rel="modulepreload">`는 첫 로드 성능을 해치므로 idle prefetch를 권장). 첫 사용 시 "처리 도구 준비 중(처음 한 번만)" 문구를 넣으세요.
- **파일 목록 compact 모드**: 한 줄 72px 안팎(썸네일 48×64, 이름과 쪽·크기, 오른쪽에 ↑↓🗑 아이콘 버튼 44px). 데스크톱은 드래그 정렬을 추가하되 위로·아래로 버튼은 접근성을 위해 유지하세요. 모바일은 **하단 고정 액션 바**("PDF 3개 합치기" + 파일 추가)를 두세요.
- **비PDF는 목록에 넣지 말 것**: 걸러 내고 목록 위에 "2개 파일은 PDF가 아니어서 제외했습니다(notes.txt, photo.jpg)"를 한 번 알리세요. 손상 파일이나 비밀번호 파일처럼 사용자 조치가 필요한 것만 목록에 남깁니다. 오류 카드가 여러 개면 "문제 파일 모두 빼기" 버튼을 두세요.
- **크기 표기**: 1 MB 미만은 KB로 표시하세요(`1.2 KB`, `94 KB`). 0.1 MB 하한 표기는 사진 도구에서 치명적입니다.
- **결과 화면 순서(모바일)**: 헤드라인(용량 전후) → **[내려받기]** → 파일 이름 → 미리보기(가로 2열 축소 또는 "미리보기 보기" 접기). 결과가 나타나면 결과 박스 상단으로 스크롤하고, 포커스는 헤드라인(`tabindex=-1`)에 두는 편이 화면에 보여 안전합니다.
- **결과 파일 이름 표시와 수정**: "저장될 이름: 이력서_홍길동 (최종)_압축.pdf [이름 바꾸기]".
- **목표 용량 모드(줄이기)**: "제출처 용량 제한" 칩(3 MB · 5 MB · 10 MB · 20 MB · 직접 입력) → 조건을 만족하는 가장 높은 화질 단계를 자동으로 고르고 결과에 "✓ 10 MB 제한 통과"를 표시합니다. 이 기능이 없더라도 결과에 "5 MB 이하 제출처에 올릴 수 있습니다" 문구는 바로 넣을 수 있습니다.
- **미리보기 확대 비교**: 결과 미리보기를 누르면 원본과 결과를 같은 위치에서 확대(돋보기 또는 슬라이더)해 볼 수 있게 하세요.
- **처리 중 문구**: "구조 정리 중…" → "파일 분석 중…", "이미지 줄이는 중… (3/12쪽)". 막대가 움직이지 않는 구간에는 경과 시간이나 쪽 수를 표시하세요.
- **"처음부터"** → "다른 파일 처리하기"(무엇이 일어나는지 말하는 버튼).
- **터치 기기에서는 끌어다 놓기 안내 숨김**: `@media (pointer: coarse)`일 때 드롭 안내를 "휴대폰의 '파일' 앱이나 다운로드 폴더에서 고를 수 있습니다"로 바꾸세요.

## 11. 교차 디자인 시스템 권고 (사진 용량 줄이기 · 여권·증명사진 · HWP→PDF에 공통 적용)

1. **도구 셸 컴포넌트 하나로 통일**: `ToolShell` = 제목과 리드 → 드롭존 → (파일 카드 또는 목록) → 설정 → 주 버튼 → 진행 → 결과 → 관련 도구. 상태 머신(`empty | loading-engine | listing/ready | confirm | working | done | kept | error | engine-error`)을 공통 모듈로 두고, **`engine-error`를 파일 오류와 반드시 분리**하세요(P0-1 재발 방지).
2. **결과 박스 표준 순서**: ① 성공 헤드라인(전후 수치: "2.4 MB → 480 KB", "413×531 px · 58 KB") ② 제출 조건 통과 칩("✓ 정부24 여권사진 규격", "✓ 500 KB 이하") ③ **[내려받기]** ④ 저장될 파일명(수정 가능) ⑤ 보조 버튼(다른 설정으로 다시, 다른 파일 처리하기) ⑥ 미리보기(확대 비교) ⑦ 다음 도구 제안. 모바일에서는 ①–③이 첫 화면에 보여야 합니다.
3. **목표 기반 입력을 1급 옵션으로**: 사진 줄이기는 "KB 목표"(100·200·500 KB·직접 입력), 여권사진은 "제출처 프리셋"(정부24 여권, 외교부, 주민등록증, 운전면허, 이력서 3×4), HWP는 "용지와 여백 유지"를 넣으세요. 기술 수치(ppi, 품질 %)는 "자세히"에 숨깁니다.
4. **크기와 단위 포맷터 공통화**: B, KB, MB 자동 선택(1 MB 미만은 KB, 소수 1자리), "%"는 붙여 쓰기, 픽셀은 "413×531 px", 인쇄 크기는 "3.5×4.5 cm". 사진 도구는 KB 정밀도가 핵심입니다.
5. **입력 수용 정책**: 도구가 받을 수 없는 형식은 목록에 넣지 말고 한 줄 요약으로 알리세요. 받는 형식(`JPG·PNG·HEIC`, `HWP·HWPX`)을 드롭존에 명시합니다. **HEIC(아이폰 기본 사진) 지원 여부**는 사진 도구의 성패를 가르니 드롭존 문구에 명확히 쓰세요.
6. **모바일 파일 선택**: 사진 도구는 `accept="image/*"`로 사진 보관함을 열고, 여권사진은 "사진 찍기"(`capture="user"`)와 "앨범에서 고르기" 두 버튼을 두세요. 터치 기기에서는 끌어다 놓기 안내를 숨깁니다. HWP는 "카카오톡으로 받은 파일은 '파일' 앱 → 카카오톡 폴더"처럼 **받은 파일 찾는 법** 도움말을 넣으세요(고령층 핵심 장벽).
7. **엔진 로딩 UX 공통화**: 페이지 idle 시 prefetch, 첫 사용 문구 "처리 도구 준비 중(처음 한 번만, 약 N MB)", SW 프리캐시. HWP 엔진처럼 무거운 것은 크기를 명시하고 셀룰러 경고를 띄우세요.
8. **개인정보 민감도 표시**: 여권사진과 HWP(주민번호가 담긴 서류)는 드롭존 위에 "이 사진은 기기 밖으로 나가지 않습니다" 배지를 크게 두세요. 사진 도구는 **EXIF GPS 제거를 기본값**으로 하고 결과에 "위치 정보 삭제됨"을 표시하세요(fixture `exif6_gps.jpg` 활용).
9. **여권사진 특화**: "보정·배경 합성 없음" 원칙을 결과 화면에서도 다시 알리고, 규격 가이드 오버레이(얼굴 길이 범위, 여백)와 "규격 통과, 확인 필요" 체크리스트를 **판정이 아닌 안내**로 표현하세요(책임 한계, 이용약관과 연계).
10. **토큰과 컴포넌트 확장**: `--success`, `--success-soft`(완료 상태) 추가, 상태 아이콘 세트(파일 형식별, 잠김, 오류, 완료), 타이포 스케일 명문화(H1 40/32, H2 28/24, 본문 16/17, 보조 14. 13px 금지), 간격 4의 배수 스케일, 버튼 높이 44/52. 굵기 표현은 P0-5 결과에 따라 static 폴백을 포함하세요.
11. **글꼴 서브셋 관리**: `Anolim UI Sans`는 현재 사용 중인 음절만 담고 있으므로, 새 도구의 카피가 추가되면 **서브셋 재생성을 빌드 단계에서 자동화**하세요(누락 음절은 Pretendard로 폴백되어 한 단어 안에서 글꼴이 섞임).
12. **카피 규칙(docs/COPY.md에 추가 권장)**: 합니다체, 보조용언 띄어쓰기("받아 주세요"), 숫자와 % 붙여 쓰기, 전문용어는 괄호 속 보조 표기, 버튼은 동사형으로 결과를 말하기("사진 줄이기", "PDF로 저장"), 오류는 "파일명 + 원인 + 할 일" 3요소.
13. **광고 안전 영역**: `ToolShell` 안에는 광고 슬롯을 두지 못하게 컴포넌트 차원에서 막고, 슬롯은 셸 밖(`AdSlot min-height`)에만 두세요.
14. **QA 게이트**: 새 도구마다 이번 감사의 스크립트 세트를 돌리세요(상태 순회, 오프라인과 청크 404, Slow 4G 첫 사용 시간, 모바일 결과 화면에서 주 버튼이 뷰포트 안에 있는지, axe, CLS, WebKit 굵기).
